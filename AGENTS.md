# Medical Bill Guardian architecture

The React/Vite receipt interface (`src/components/`, `src/App.tsx`) is adapted from `codex/receipt-trace-demo`; the backend (`spacetimedb/`) is based on `feat/spacetimedb-backend`. This integration branch intentionally uses SpacetimeDB, not the earlier Next.js/SQLite runtime. Do not reintroduce browser-side bank, EHR, or email secrets.

`spacetimedb/src/schema.ts` defines private case, evidence, audit, communication, owner-config, and email-deduplication tables. `spacetimedb/src/index.ts` owns state transitions. Browser clients read only owner-filtered views and can initiate only owner-authorized reducers. The Worker holds the database publisher token and alone can import external cases, mark Resend sends, and ingest replies. `module_owner` is initialized on first publish, so use a fresh database when changing from an older module without that table. Generated bindings live in `src/module_bindings/`; regenerate after schema or reducer edits.

`spacetimedb/src/logic/` parses and reconciles deterministic bill facts. Missing clinical evidence is a review request, not a proven billing error. Only the synthetic mock provider response confirms the $700 adjustment. The real email reply reducer records that a response arrived but never changes savings until independent verification exists. The browser reassembles view rows in `src/lib/assemble.ts`.

`worker/index.ts` serves Vite assets, an authenticated sandbox-discovery endpoint, a scheduled Resend outbox, and the `ai@nipunsaini.com` inbound email handler. `worker/sandbox.ts` verifies a browser SpacetimeDB token before import. `src/integrations/sandbox-evidence.ts` uses Nessie and FinchNode when configured; a missing Nessie transaction opens a clearly labeled mock case, while missing FinchNode records on a Nessie case remain empty. `worker/mime.ts` parses bounded MIME and one text PDF in the synthetic statement grammar. Unknown layouts and image-only PDFs remain pending. `worker/db.ts` maps private SpacetimeDB SQL rows and calls publisher-only reducers. The recipient in `worker/resend.ts` is the test inbox `nipun.saini9@gmail.com`, not the hospital.

Cloudflare config is `wrangler.jsonc`; `addresses` adds only the `ai@nipunsaini.com` route. The deployed database is `medical-bill-guardian-email` on maincloud. The Worker is `medical-bill-guardian`. `EMAIL_SEND_ENABLED` defaults false. Secrets `SPACETIME_OWNER_TOKEN` and `RESEND_API_KEY` belong only in Wrangler secrets; optional Nessie and FinchNode keys also belong there. `.env` and `.env.local` are ignored. Do not put actual patient information in this synthetic deployment; there is no patient login, consent grant UI, or encrypted clinical storage. A Cloudflare tunnel is useful for temporary local development but is not needed for the cloud database; close quick tunnels after use.

Local run: `npm ci`, `npm ci --prefix spacetimedb`, `cp .env.example .env.local`, `spacetime start` (port 3000), `spacetime publish -s local --module-path spacetimedb medical-bill-guardian`, `npm run spacetime:generate`, `npm run dev` (port 5173). Verify with `npm test`, `npm run build`, `npm run smoke`; `npm run smoke` owns port 3100 and must never manipulate a preexisting server. Deployment: build with cloud `VITE_SPACETIMEDB_HOST` and `VITE_SPACETIMEDB_DB_NAME`, then `npx wrangler deploy`. Keep tests and documentation in the same commit as related changes.
