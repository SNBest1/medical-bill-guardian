# Medical Bill Guardian architecture

The backend is a SpacetimeDB TypeScript module in `spacetimedb/`; the frontend is a Vite React app in `src/`. There is no Next.js, API route, or SQLite layer anymore.

`spacetimedb/src/schema.ts` defines eight private tables: `bill_case` plus child tables (`medical_record`, `bill_item`, `finding`, `timeline_event`, `audit_entry`, `communication`) that each carry `case_id` and an indexed `owner`, and the schedule table `bill_delivery`. `spacetimedb/src/index.ts` holds the reducers, the scheduled `deliver_bill`, and seven public views (`my_cases`, `my_timeline`, …) that each return only rows whose `owner` is `ctx.sender`. Never mark a table `public: true`: every viewer would receive every other viewer's cases.

The state machine: `scan_demo_payment` opens one case per owner (repeat calls are no-ops); `investigate_case` inserts the mock records, a pending bill request, and a `bill_delivery` row for two seconds later, then waits at `WAITING_FOR_BILL`; `deliver_bill` parses the statement, reconciles each charge, and stops at `REVIEW_REQUIRED` when evidence is missing; `authorize_review` (owner only) records the mock provider correction and finishes the case at `USER_NOTIFIED`; `reset_demo` deletes the caller's rows including any pending delivery. `deliver_bill` rejects any caller other than `ctx.databaseIdentity`, so clients cannot force the bill.

`spacetimedb/src/logic/` is pure TypeScript with no SpacetimeDB imports: `parse-bill`, `matcher`, `reconcile` (missing evidence is "needs review", never a confirmed error), `summary`, `money`, and the demo `fixtures`. Reducers and this logic must not use `Date.now`, `Math.random`, `crypto`, or `Intl`/`toLocaleString`; time comes from `ctx.timestamp`, and `formatDollars` exists because modules may lack `Intl`. Money is integer cents.

The client (`src/main.tsx`, `src/App.tsx`) subscribes to the views with `useTable`, calls reducers with `useReducer`, and converts rows to the display model in `src/types/domain.ts` (dollars) through `src/lib/assemble.ts` — the only place rows become display types. `src/module_bindings/` is generated by `npm run spacetime:generate` and committed; regenerate after any schema or reducer change.

`src/services/banking/nessie.ts` and `src/services/medical/finchnode.ts` are unused reference adapters (not bundled). The Nessie sandbox IDs live only in the ignored `.env`. FinchNode has no authenticated subject yet. The Relay CLI is pinned in `devDependencies` (`./node_modules/.bin/relay`); the staging agent handle is `medical_bill_guardian`, its token belongs only in `.env` or Relay's private profile, and agent access-policy changes need explicit approval. Relay calls reach chat participants, not hospital phone lines.

The module has no network calls and contains only mock providers. Do not add live integrations until user identity, per-patient consent, encrypted storage, and a live communication adapter exist.

Run: `npm ci`, `npm ci --prefix spacetimedb`, `cp .env.example .env.local`, `spacetime start` (port 3000), `spacetime publish -s local --module-path spacetimedb medical-bill-guardian`, `npm run spacetime:generate`, `npm run dev` (port 5173). Verify with `npm test`, `npm run typecheck`, `npm run build`, `npm run smoke` (own server on port 3100). Keep `.env`, `.env.local`, `data/`, and `dist/` out of Git.
